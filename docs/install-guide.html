1. Kiến trúc tham chiếu

VNSO CloudStack chia làm 4 lớp logic: access, management, compute, storage. Mỗi lớp tách VLAN riêng và có ít nhất 2 path redundancy.

Bảng dưới được rút từ Apache CloudStack capacity guide kết hợp benchmark VNSO trên Intel Sapphire Rapids + NVMe Gen4.

Công thức nhanh

  • vCPU host = (VM_count × avg_vCPU) / overcommit_ratio với overcommit thường 4:1.
  • RAM host = (VM_count × avg_RAM) / 0.85 (giữ 15 % cho hypervisor + balloon).
  • IOPS Primary = VM_count × avg_iops_per_vm × 1.3 (peak factor).
  • Bandwidth guest = VM_count × avg_mbps × 0.6 (giả định non-coincidence 60 %).

Secondary storage

  • NFS: đơn giản, mount thẳng vào SSVM. Phù hợp ≤ 50 TB.
  • S3 (Cloudian / MinIO): scale > 100 TB, lifecycle & cross-region.
  • Hybrid: NFS cache + S3 long-term (CloudStack hỗ trợ object_store).

Khuyến nghị I/O

NFS export options:
  rw,sync,no_subtree_check,no_root_squash,fsid=1

XFS mount cho hypervisor:
  noatime,nodiratime,inode64,allocsize=1m,logbufs=8,logbsize=256k

Ceph pool:
  osd pool create primary 256 256 replicated
  ceph osd pool application enable primary rbd
  ceph osd pool set primary size 3 min_size 2

6. Chuẩn bị host vật lý

BIOS & firmware

  • Bật Intel VT-x / AMD-V, IOMMU, SR-IOV (nếu cần).
  • Vô hiệu hóa C-states sâu hơn C1 cho workload latency-critical.
  • Cập nhật firmware NIC, RAID, BMC theo bản LTS.

OS baseline

# Rocky 9 / Ubuntu 22.04 minimal
sudo dnf groupinstall -y "Development Tools" || sudo apt -y install build-essential
sudo systemctl disable --now firewalld; sudo systemctl enable --now nftables
sudo timedatectl set-timezone Asia/Ho_Chi_Minh
sudo systemctl enable --now chronyd
sudo sed -i 's/SELINUX=enforcing/SELINUX=permissive/' /etc/selinux/config  # KVM host
sudo sysctl -w vm.swappiness=10 fs.file-max=2097152 net.core.somaxconn=65535

Mạng (LACP bond + VLAN)

# /etc/systemd/network/10-bond0.netdev
[NetDev]
Name=bond0
Kind=bond
[Bond]
Mode=802.3ad
LACPTransmitRate=fast
TransmitHashPolicy=layer3+4

# /etc/systemd/network/20-bond0.network
[Match]
Name=bond0
[Network]
VLAN=mgmt
VLAN=storage
VLAN=guest

Kernel tuning cho KVM

cat <<EOF | sudo tee /etc/sysctl.d/90-cloudstack.conf
net.bridge.bridge-nf-call-iptables = 0
net.ipv4.ip_forward = 1
vm.dirty_ratio = 20
vm.dirty_background_ratio = 5
EOF
sudo sysctl --system

7. Management Server cluster

Dùng Docker compose (image VNSO build) hoặc package Debian/RPM. Khuyến nghị 2-3 node sau LB.

7.1. Triển khai bằng compose (PoC)

git clone https://github.com/trinhtanphat/cloudstack.git
cd cloudstack
git checkout vnso
docker compose -f docker-compose.prod.yml up -d
# Theo dõi
docker compose logs -f cloudstack-mgmt | grep -E 'ERROR|Started|listening'

File docker-compose.prod.yml đã có:

  • wait-for-DB entrypoint chờ MySQL TCP + handshake trước khi khởi Java.
  • healthcheck probe /client/ (200/302/401), start_period 180 s, retries 6.
  • restart: unless-stopped + stop_grace_period: 60s.

7.2. Triển khai 2-3 node (HA)

# Trên cả 3 node
cp docker-compose.prod.yml docker-compose.yml
docker compose up -d

# nginx LB (host kế bên)
upstream cloudstack_mgmt {
    least_conn;
    server mgmt-1.vnso.local:28080 max_fails=2 fail_timeout=15s;
    server mgmt-2.vnso.local:28080 max_fails=2 fail_timeout=15s;
    server mgmt-3.vnso.local:28080 max_fails=2 fail_timeout=15s;
    keepalive 64;
}
server {
    listen 443 ssl http2;
    server_name manage.example.vn;
    ssl_certificate     /etc/letsencrypt/live/manage.example.vn/fullchain.pem;
    ssl_certificate_key /etc/letsencrypt/live/manage.example.vn/privkey.pem;
    include /etc/nginx/conf.d/vnso-cloudstack-headers.inc;
    location /client/ { proxy_pass http://cloudstack_mgmt/client/; }
}

8. MySQL InnoDB Cluster

# Trên tất cả 3 node DB
sudo dnf -y install mysql-shell mysql-router mysql-server
sudo systemctl enable --now mysqld
mysqlsh --uri root@localhost --sql -e "SET GLOBAL super_read_only=OFF;"

# Trên node-1 (primary bootstrap)
mysqlsh --uri clusteradm@db-1 -- dba configure-instance --interactive=false
mysqlsh --uri clusteradm@db-1 -- dba create-cluster vnso
mysqlsh --uri clusteradm@db-1 -- cluster add-instance db-2 --recovery-method=clone
mysqlsh --uri clusteradm@db-1 -- cluster add-instance db-3 --recovery-method=clone

# MySQL Router (chạy trên mỗi management node)
mysqlrouter --bootstrap clusteradm@db-1:3306 \
  --conf-base-port 6446 --user mysqlrouter
sudo systemctl enable --now mysqlrouter

# Trỏ CloudStack tới router
sed -i 's|db.cloud.host=.*|db.cloud.host=127.0.0.1|; s|db.cloud.port=.*|db.cloud.port=6446|' \
    /etc/cloudstack/management/db.properties
Quan trọng: không để DB trên cùng compose project khác mà không có healthcheck — nếu MySQL phải chạy InnoDB recovery, mgmt sẽ chết Hikari pool và trả 503 ở /client/. File compose VNSO đã thêm wait-for-DB entrypoint để xử lý trường hợp này.

9. Cài KVM host

sudo dnf -y install qemu-kvm libvirt cloudstack-agent
sudo systemctl enable --now libvirtd
sudo systemctl enable --now cloudstack-agent

# /etc/cloudstack/agent/agent.properties
host=mgmt.vnso.local
guid=$(uuidgen)
public.network.device=cloudbr0
private.network.device=cloudbr1
storage.network.device=cloudbr2
hypervisor.type=kvm

# bridge cloudbr0/1/2 dùng NetworkManager hoặc systemd-networkd

Sau đó vào UI → Infrastructure → Hosts → Add Host, nhập IP + root credentials. Agent sẽ tự đăng ký, chuyển trạng thái Up trong 1-2 phút.

10. Zone / Pod / Cluster

Khái niệmVai tròGhi chú
ZoneDatacenter logic, có Public + Guest network riêng1 zone = 1 site Active-Active
PodSubnet management, gateway riêng1-2 pod / zone là đủ với SMB
ClusterNhóm host cùng hypervisor + primary storage≤ 16 host / cluster (best practice KVM)
Host1 hypervisorĐã đăng ký agent

Wizard Add Zone:

  1. Network type: Advanced (chọn Security Groups nếu KVM flat).
  2. DNS: 1.1.1.1, 8.8.8.8 (hoặc DNS nội bộ).
  3. Domain: vnso.local.
  4. Physical network: kéo các traffic Management/Public/Guest/Storage vào NIC tương ứng.
  5. VLAN range: 100-3999 cho guest.
  6. Public IP range: 203.0.113.10 - 203.0.113.250.
  7. Pod: gateway 10.20.0.1, range 10.20.0.10-10.20.0.250.
  8. Cluster + Host: thêm host KVM với credentials.
  9. Primary storage: nfs://10.40.0.10/export/primary.
  10. Secondary: nfs://10.40.0.10/export/secondary.
  11. Launch zone: chờ SSVM/CPVM chuyển Running (5-10 phút).

12. Hardening & TLS

Sao chép snippets nginx VNSO đã chuẩn bị:

sudo cp scripts/vnso/nginx/hardening.conf /etc/nginx/conf.d/
sudo cp scripts/vnso/nginx/headers.inc    /etc/nginx/conf.d/
sudo cp scripts/vnso/nginx/locations.example.conf /etc/nginx/conf.d/vnso-cloudstack.conf
sudo certbot --nginx -d manage.example.vn
sudo nginx -t && sudo systemctl reload nginx
  • TLS 1.2/1.3, HSTS 2 năm, OCSP stapling.
  • CSP, COOP, CORP, X-Content-Type-Options, Referrer-Policy.
  • Rate-limit zone vnso_login (5 r/s) + vnso_api (30 r/s).
  • Bật 2FA cho admin (TOTP), enforce password complexity (xem Security).
  • Rotate API key 90 ngày: scripts/vnso/rotate-admin-api-key.sh.
  • Audit log forward sang ELK / Loki.

13. Monitoring & alert

Stack đề xuất

  • Prometheus + node_exporter + libvirt_exporter + mysqld_exporter + cloudstack_exporter.
  • Grafana dashboards: scripts/vnso/grafana/*.json.
  • Alertmanager → Slack / email / SMS Stringee.

Alert rule mẫu

groups:
- name: vnso-cloudstack
  rules:
  - alert: MgmtHTTP503
    expr: probe_http_status_code{instance=~"https://manage.+/client/"} == 503
    for: 2m
    labels: { severity: critical }
    annotations:
      summary: "CloudStack mgmt 503 over 2 minutes"
      runbook: "https://docs-cloudstack.vnso.vn/operations.html#mgmt-503"
  - alert: PrimaryStorageFull
    expr: cloudstack_storage_pool_used_pct > 0.85
    for: 5m
    labels: { severity: warning }
  - alert: KVMHostDown
    expr: up{job="libvirt"} == 0
    for: 1m
    labels: { severity: critical }

15.3. Lệnh xuất báo cáo từ DB

-- Tổng VM theo zone
SELECT z.name AS zone, COUNT(*) AS vm_count
  FROM vm_instance v JOIN data_center z ON v.data_center_id = z.id
  WHERE v.removed IS NULL
  GROUP BY z.name;

-- Capacity overview
SELECT capacity_type, SUM(used_capacity)/1e9 AS used_gb,
       SUM(total_capacity)/1e9 AS total_gb,
       ROUND(SUM(used_capacity)/SUM(total_capacity)*100,2) AS pct
  FROM op_host_capacity
  GROUP BY capacity_type;

-- Top 10 VM theo CPU usage
SELECT vm.instance_name, vm.service_offering_id, st.cpu_used
  FROM vm_instance vm JOIN op_vm_stats st ON st.vm_id = vm.id
  ORDER BY st.cpu_used DESC LIMIT 10;
