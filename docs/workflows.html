Workflows & sơ đồ vận hành

Sơ đồ kiến trúc, luồng nghiệp vụ chính, và CI/CD release pipeline.

1. Kiến trúc tổng thể

2. Luồng deploy một VM

  1. Client gọi deployVirtualMachine qua REST API (HMAC-SHA1 signature).
  2. Nginx kiểm TLS, áp rate-limit, forward về Management cluster.
  3. Management Server xác thực API key, kiểm RBAC, ghi async_job, trả jobid.
  4. Resource Manager chọn host (capacity + affinity), reserve resource trong DB.
  5. Hypervisor agent nhận StartCommand, tạo VM (libvirt/vSphere SDK/...).
  6. SystemVM (VR) cấu hình DHCP/DNS/firewall cho guest network.
  7. Usage service ghi event để billing/quota tính tiền.
  8. Client poll queryAsyncJobResult → trạng thái SUCCEEDED + IP/credentials.

3. CI/CD release pipeline

Cách phát hành bản mới

  1. Cập nhật version ở desktop/package.json, mobile/package.json, extension/manifest.json.
  2. Tạo tag: git tag clients-v1.0.1 && git push origin clients-v1.0.1.
  3. Workflow .github/workflows/release-clients.yml tự build & upload tất cả nền tảng.
  4. Mở GitHub Releases, kiểm các tệp .AppImage / .dmg / .exe / .apk / .zip / .tar.gz.
  5. (Tuỳ chọn) Bật biến IOS_BUILD_ENABLED=true trong repo variables để build IPA.

4. Luồng bulk deploy 1000 VM

  1. Người dùng tải file YAML/JSON spec, chọn template + zone + offering.
  2. Plugin bulk-service chia batch (mặc định 50/lô), đẩy vào worker pool.
  3. Mỗi worker gọi deployVirtualMachine với retry exponential (3 lần, 1s/3s/9s).
  4. UI BulkJobProgress.vue theo dõi qua polling listCatalogDeploymentStatus.
  5. Khi tỉ lệ lỗi > ngưỡng (ví dụ 20%), batch tự rollback VM đã tạo.
  6. Báo cáo kết quả: số ok/fail, tổng wall-time, P95 latency, link CSV usage.

5. Luồng quên mật khẩu

  1. Người dùng nhấn Quên mật khẩu trên màn hình đăng nhập.
  2. UI gọi forgotPassword, người dùng nhập username + email.
  3. Management Server tạo token một lần, gửi link reset-password?token=... qua SMTP.
  4. Người dùng mở link → nhập mật khẩu mới (≥ 12 ký tự, qua zxcvbn check).
  5. Token bị huỷ; sự kiện log vào bảng cloud.event để audit.

6. Disaster Recovery

  1. Backup MySQL hằng ngày bằng xtrabackup → S3 (Cloudian / GCS).
  2. Secondary storage replicate cross-zone (rclone hoặc rsync over WireGuard).
  3. Diễn tập restore staging hằng tháng — runbook ở Zone-2 Stabilization Runbook.
  4. RTO mục tiêu < 4h, RPO < 24h cho deploy production.
